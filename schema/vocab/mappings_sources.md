# Sources for the UBEM concept mappings

All files were retrieved on 2026-11-13. They are treated as data only: they were parsed and never executed. Every `target_id` in `mappings.csv` was resolved against these files by script, and a second, independent check confirmed each one verbatim (168/168 passed). Mappings to deprecated Brick classes were dropped automatically.

## Brick Schema (`brick/Brick.ttl`)
- URL: https://github.com/BrickSchema/Brick/releases/download/v1.4.4/Brick.ttl
- Version: v1.4.4 (GitHub release published 2025-05-02; the file has `owl:versionInfo "1.4.4"`). This is the latest 1.4.x release. v1.5.0 also exists but was not used, per the brief.
- SHA-256: b65720b7b9b64c646745c689777e6138c0d59ce0088df0aeb78fbd444d04d8e7
- Parsed with rdflib 7.6.0. The term index has 1,514 Brick-namespace classes and properties.
- In 1.4.x, Brick deprecates its location classes (Location, Region, Building, Space, Room, Basement and others) and `Zone_Air_Temperature_Setpoint` (`owl:deprecated true`). Where a mapping was still useful, it points to the RealEstateCore class that the release itself names as the replacement. That class is bundled in the same Brick.ttl file (`rec:` = https://w3id.org/rec#). Those rows keep `standard = brick` and say so in the note.

## BEDES (`bedes/bedes_v2.5_uuid-terms.xml`, `bedes/bedes_v2.5_uuid-lo.xml`)
- The official site (bedes.lbl.gov, which redirects to bies.lbl.gov/cbs/bedes/) serves a Cloudflare JavaScript challenge, and every URL tried, including the API, returned 403. It was not bypassed.
- Instead, the BEDES online-dictionary exports (terms plus list options, with Content-UUIDs and URLs) were taken from the BuildingSync project's own repository, pinned to a commit:
  - https://raw.githubusercontent.com/BuildingSync/BuildingSync-website/8cc6b42445de05bc25afc7327a0059da12ef2a69/bsyncviewer/lib/bedes/v2.5/bedes_online_dictionary_uuid-terms.xml
  - https://raw.githubusercontent.com/BuildingSync/BuildingSync-website/8cc6b42445de05bc25afc7327a0059da12ef2a69/bsyncviewer/lib/bedes/v2.5/bedes_online_dictionary_uuid-lo.xml
- Version: BEDES V2.5, as labelled by the BuildingSync folder. The commit is dated 2021-12-28 and the latest Updated-Date inside the file is 2021-09-16.
- SHA-256: terms 74159dea60af9e054ed587be3b197a0d3b882d5da4e0018238cbacaa1bb9af28; list options 5cfdddf2e40626e5e893aa9e5442f5786dd1d04d28ead915914b041a213701a9
- Contents: 659 terms and 5,558 list options. `target_id` is the BEDES node URL `https://bedes.lbl.gov/node/<Content-UUID>`, copied verbatim from the XML.
- For list-option targets, `target_label` names the parent term (for example "Gross (list option of Floor Area Qualifier)"). Many BEDES concepts are composites (for example, gross floor area = Area + Floor Area Qualifier=Gross). The note says when this applies.
- Caveat: this copy is not fetched from bedes.lbl.gov itself. A co-author with browser access may want to spot-check a few UUID URLs against the live site.

## CityGML Energy ADE (`energy_ade/EnergyADE.xsd`)
- URL: https://www.sig3d.org/citygml/2.0/energy/1.0/EnergyADE.xsd (the schema location of the official namespace)
- Version: Energy ADE 1.0 for CityGML 2.0. The schema has `version="1.0"` and its header says it was generated by the KIT UML-to-XML tool on 2017-12-20. The Energy ADE 3.0 beta for CityGML 3.0 (tudelft3d/Energy_ADE, `Energy_ADE_3.0_beta7.xsd`) was not used.
- SHA-256: 5a771f5ef702f86fedcabb24fce9a1d6ac3c0761a89aad3ea0ab7891ed280817
- The XSD defines no per-term IRIs, so `target_id` is built as follows:
  - `<namespace>#<GlobalElementOrType>` for global elements, for example `http://www.sig3d.org/citygml/2.0/energy/1.0#WeatherData`.
  - `<namespace>#<ParentType>/<member>` for a property inside a complex type, or an enumeration value inside a simple type, for example `...#WeatherDataTypeValue/airTemperature`.
  - Each name was confirmed verbatim in the XSD, inside the stated parent type.

## Scripts (kept outside the download folders)
`../mapscripts/parse_sources.py` builds the term indexes. `../mapscripts/mapping_spec.py` holds the proposed mappings. `../mapscripts/build_mappings.py` resolves and verifies them, drops any that fail or are deprecated, and writes `mappings.csv`.
