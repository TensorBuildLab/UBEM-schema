# UBEM-Link

**An AI-ready schema, open-data catalog and tool for urban building energy modeling (UBEM).**

UBEM combines weather, building geometry, building characteristics, occupant behavior and measured energy use,
mostly from open data that were never designed to fit together. UBEM-Link is a shared, machine-checkable
description of those data, in the spirit of what Brick and Project Haystack provide for building operational
data:

- a **taxonomy** of open UBEM data by the model input it serves, with six independent facets (role, statistical
  nature, spatial granularity, temporal resolution, access, join keys);
- **category profiles** stating what a modeler must know about each kind of data (weather year type and timestamp
  convention; geometry dimension, level of detail and height reference; behavior types; data form and
  representativeness of characteristics; scale, metering level and measurement basis of energy data);
- **variable profiles** stating what each column means: concept, unit, multiplier, missing codes, code list,
  weight or imputation flag, join key;
- a **concept vocabulary** of 73 defined concepts linked to Brick, BEDES and the CityGML Energy ADE;
- **conventions** that publishers state once for many columns, with a machine-readable scope;
- a **catalog** of 93 open datasets described with the schema;
- the **`ubem-link` tool**, which turns a dataset and its codebook into a profile with a local or hosted language
  model, applies the profile, and integrates several datasets into one table.

The taxonomy and category profiles refine the seven-category taxonomy and per-category metadata of Zhang, Chen and
Zou (2023), *Taxonomy, Semantic Data Schema, and Schema Alignment for Open Data in Urban Building Energy Modeling*,
arXiv:2311.08535.

## Quick start

```bash
git clone https://github.com/TensorBuildLab/UBEM-schema && cd UBEM-schema
pip install -e .
ollama pull qwen3:8b && ollama pull nomic-embed-text          # local models, https://ollama.com

# profile a dataset you have never seen, with its portal dictionary and the publisher's metadata page
ubem-link describe examples/nyc/footprints_sample.csv \
    --codebook examples/nyc/footprints_dictionary.json examples/nyc/footprints_metadata.md \
    --entry geo-nyc-footprints --out out/
ubem-link validate out/geo-nyc-footprints.ubem.yaml           # schema errors and open review flags
ubem-link apply out/geo-nyc-footprints.ubem.yaml examples/nyc/footprints_sample.csv -o out/footprints_si.csv

# join benchmarking, tax lots, footprints and weather into one UBEM input table
python scripts/download_nyc.py --only weather
cd examples/nyc && ubem-link integrate recipe.yaml -o ../../out/nyc_ubem_inputs.csv
```

Without a local model, use `--model files:work/` and let an assistant such as Claude Code answer the requests (see
[tutorial 4](docs/tutorials/04-assistants-and-apis.md)), or `--model openai:<name>` with any OpenAI-compatible
server, or `--model anthropic:<name>`.

## Repository layout

| Path | Content |
|---|---|
| `schema/ubem_link.yaml` | The schema (LinkML), the single source of truth |
| `schema/vocab/` | Concept vocabulary, unit vocabulary, mapping sources |
| `schema/mappings/ubem_link.sssom.tsv` | 168 mappings to Brick 1.4.4, BEDES 2.5 and the CityGML Energy ADE 1.0 (SSSOM) |
| `schema/generated/` | JSON Schema, SHACL shapes, OWL ontology |
| `schema/ai/` | Schema card, concept cards and dataset cards for AI systems |
| `catalog/datasets/` | 93 dataset profiles; `catalog/category_profiles_provenance.csv` records how each category profile was drafted |
| `examples/nyc/` | Sample data, reviewed profiles and an integration recipe |
| `src/ubem_link/` | The Python package and the `ubem-link` tool |
| `docs/` | Documentation (`mkdocs serve` to browse) |
| `benchmark/`, `paper/` | The experiments of the companion paper, with cached model outputs; every number and figure is regenerated from them |

## Reproducing the paper

```bash
pip install -e ".[dev]"
python scripts/download_data.py && python scripts/download_nyc.py && python scripts/download_nyc.py --geometry
python -m ubem_link.bench score && python -m ubem_link.bench_report && python -m ubem_link.design_report
python -m ubem_link.revision_stats && python -m ubem_link.endtoend && python -m ubem_link.city
python -m ubem_link.city_integration
pytest -q
```

Model calls are cached in `benchmark/results/cache/`, so these commands reproduce the results without a GPU.
`scripts/run_*.sh` rerun the model calls (Ollama; Qwen3 8B and 14B, Llama 3.1 8B).
